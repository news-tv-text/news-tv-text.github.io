# story/ — телетекст-декодер «Лампы через одну»

Статический раздел: рассказ подан как декодер телетекста. Страницы набираются
тремя цифрами, числа из текста работают как настоящие номера страниц,
`214` открывается только после всех глав и трёх найденных номеров.

## Файлы

| файл | что это |
| --- | --- |
| `index.html`, `story.css`, `story.js` | сам декодер |
| `content.json` | собирается скриптом, руками не правится |
| `README.md` | этот файл |

Текст живёт в `stories/lampy-cherez-odnu.md`, квестовые данные — в
`stories/meta.json`. После правки любого из них:

```bash
python3 stories/build_content.py          # пересобрать story/content.json
python3 stories/build_preview.py out.html # однофайловая версия, необязательно
```

CI проверяет, что `content.json` не разошёлся с рукописью, и роняет сборку,
если забыли пересобрать.

## Локальный запуск

```bash
python3 -m http.server 8000   # из корня репозитория
# http://localhost:8000/story/
```

Через `file://` не заработает: браузер не отдаст `content.json`. Если нужна
версия без сервера — соберите однофайловую через `build_preview.py`.

## Выкладка на свой сервер

Раздел статический, достаточно скопировать каталог целиком. Автоматически это
делает `.github/workflows/deploy-story.yml` — по пушу в `main` или руками из
вкладки Actions. Нужны секреты репозитория:

| секрет | обязателен | что это |
| --- | --- | --- |
| `DEPLOY_HOST` | да | хост или IP |
| `DEPLOY_USER` | да | пользователь SSH |
| `DEPLOY_PATH` | да | каталог назначения, например `/var/www/lunevo/story` |
| `DEPLOY_SSH_KEY` | да | приватный ключ целиком, вместе со строками BEGIN/END |
| `DEPLOY_PORT` | нет | порт SSH, по умолчанию 22 |
| `DEPLOY_KNOWN_HOSTS` | нет | строка из `known_hosts`; без неё ключ хоста принимается на доверии |

Пока секреты не заданы, workflow не падает — просто пишет, что деплой пропущен.

`rsync` намеренно запускается без `--delete`: при неверном `DEPLOY_PATH` этот
флаг снёс бы на сервере чужие файлы. Когда путь проверен, флаг можно добавить в
workflow — тогда удалённые из репозитория файлы будут исчезать и на сервере.

Бот в этот деплой не входит: ему нужен живой процесс, см. `bot/README.md`.
